# Paper ETFR 逆向项目 - 协议分析(决定性发现)

## 目标回顾
用第三方眼追(Paper)的注视点数据,注入 PICO 4 系统,驱动系统级注视点渲染(ETFR/动态FFR)。

## ⚠️ 决定性发现: Paper 传的是"图像",不是"坐标"
**抓包确认**(PICO 通过 UDP 发往 PC):

```
192.168.1.119:35506 → 192.168.1.110:45454  UDP length 1056~1200
```

**UDP 帧结构**(IP 头后 payload):
```
5054 0101  <- "PT" 协议标记 + 版本
0000 054c  <- 递增帧计数器
0005       <- 类型/帧 id
0000-0004  <- 分片序号(一个JPEG帧拆成多个UDP包)
04a0 0000  <- 数据长度(0x04a0=1184)
ffd8 ffe0  <- JPEG SOI 头(图像开始) ... ffd9 = 图像结束
```

**帧格式结论**:
- Paper 传感器(ESP32-S3 + 摄像头)输出**眼部灰度图像流(240×320 JPEG)**
- **不是注视点坐标!**
- 数据走 UDP,分包传输(~1200字节/片,高速实时)
- 注视点坐标**必须从图像计算出来**

## 硬件/软件架构(已完全确认)
1. **传感器**: 3 个 ESP32-S3 USB 设备(Left Eye 0425:0002 / Right Eye 0425:0003 / Face 0425:0001),CDC-ACM 串口
2. **PICO app**(com.bridge.papertracker): 用 libusb 读传感器 → 收图像
3. **数据流**: PICO app → UDP(35506) → PC(45454)
4. **PC 端 exe**(PaperTracker): 从图像算注视点(这就是"PC 负责处理数据"的本质)

## 关键瓶颈
**图像→注视点坐标的算法在 PC 端 exe / 或需自研**。这是核心 CV(计算机视觉)算法(瞳孔检测+视线估计),不是简单的 hook。

## 传输参数
- UDP 单播, PICO:35506 → PC:45454
- 图像尺寸: 240×320 灰度 JPEG
- 帧率极高(实时)
- PICO 局域网 IP: 192.168.1.119

## 抓包工具
- 设备自带 `/system/bin/tcpdump`
- 命令: tcpdump -i wlan0 -nn -X udp port 45454
